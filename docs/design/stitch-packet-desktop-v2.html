What's wrong

github.py labels each repo with project_type. The project-selection step drops the label, and transform.py never prints it, so the grader is told to score by a label it never sees.

Show full explanation

How to reproduce

1.

Configure any LLM provider and run the pipeline on a profile with a GitHub repo that has several human contributors.

2.

In generate_projects_json (github.py), print selected_projects after json.loads. The objects have no project_type or contributor_count keys.

3.

Print the output of transform.convert_github_data_to_text. Each project shows only description, URL, stars, forks and language, with no Type line.

4.

Check the evaluator's scoring evidence: it treats the projects as self_project, because criteria.jinja lines 61 and 176 key on a field it never receives.
