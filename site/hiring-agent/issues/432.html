What's wrong

The report is confirmed. `min_final_score` and `max_final_score` are parsed into `Role` in roles.py, but nothing outside roles.py reads them. `print_evaluation_results` in score.py computes the total as category scores + bonus − deductions.
Show full explanationIt caps the total only at `sum(category max) + role.bonus_max`, which is a value it recomputes on its own, and it has no lower bound. `Deductions.total` is only constrained by `ge=0`, so a large deduction can push the total below `min_final_score`. A role author who sets `max_final_score` to something other than `sum(categories) + bonus_max` sees no effect. The CSV path in transform.py is also unclamped: its `total_score` sums only the category scores and leaves out bonus and deductions. One detail differs from the report: the intern role.json in this checkout has `max_final_score` 130, not 120.
Model confidence: high.

How to reproduce

  1. Use the software_engineering_intern role, whose role.json sets min_final_score to -20.
  2. Produce or mock an evaluation whose category scores are low and whose deductions.total is large, for example 100. Deductions.total has no upper bound, only ge=0.
  3. Call print_evaluation_results(evaluation, role, ...) from score.py. The printed OVERALL SCORE is below -20 (for example -60). Nothing raises the total to min_final_score.
  4. Edit role.json to set max_final_score to a value lower than sum(category max) + bonus_max, for example 50, and use an evaluation that scores high. The printout is still capped at max_score + bonus_max, not at 50.
  5. Run `grep -rn 'min_final_score\|max_final_score' --include=*.py .`. Only roles.py matches. score.py and transform.py never reference these fields.
