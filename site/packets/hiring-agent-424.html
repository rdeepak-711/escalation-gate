What's wrong

The classification is computed in github.py but is lost twice before it reaches the evaluator. First, the selection LLM receives project_type and contributor_count as input, but the prompt's required JSON output schema omits them.
Show full explanationThe code then uses the model's returned objects directly and never re-attaches the computed fields. Second, transform.convert_github_data_to_text never prints project_type, contributor_count or author_commit_count. The rubric rules that depend on project_type therefore cannot fire, and the evaluator has to guess the type from the description. The report's claim about criteria.jinja is confirmed (line 61). The system_message.jinja claim was only partly checked: grep shows project_type on lines 24 and 71, but I did not read those lines.
Model confidence: high.

How to reproduce

  1. Run the pipeline with Ollama qwen3:8b on a GitHub profile whose top repo has more than one human contributor and at least 4 commits by the candidate.
  2. In github.py, print selected_projects right after json.loads (around line 403). The dicts only have the keys from the template's output schema, with no project_type or contributor_count.
  3. Call transform.convert_github_data_to_text on the result, or print the evaluator prompt. Each project shows only name, description, URL, stars, forks and language.
  4. The evaluator has no type information, so the rule at criteria.jinja line 61 (all projects 'self_project') gets applied from a guess.
  5. To confirm a fix, re-attach the computed fields by repo name after selection and print a Type line in convert_github_data_to_text.
